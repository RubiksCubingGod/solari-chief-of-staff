# Challenge brief (client direction)

Source: Pinetree Research SWE-intern hiring challenge, posted by @harrychow_ (received
2026-08-31). This is the external direction the project answers.

## Requirements

1. Fork the Solari repo: https://github.com/solari-sdk/solari-cookbook
   (our fork: https://github.com/RubiksCubingGod/solari-cookbook — byte-identical to upstream
   at commit d304843; the fork is a challenge formality, the product repo is this one).
2. Build a real use case with Solari (browsers, sandboxes, and/or desktops).
3. Publish it on a public GitHub account.
4. Share it in a post on LinkedIn or X, tagging @harrychow_ and @getsolari.

## Judging signals (from the poster's fact sheet)

- Use AI to build it — explicitly encouraged; shipping speed with AI is a positive signal.
- "A good use case is something with product market fit — build for the people. Something that
  solves a problem, something that you use, and something that others would use."
- Standing out means proving people need it: build in public, show it, get people to use it.
- No deadline; they hire when they find the right fit. Remote role.

## How this project answers it

Chief-of-staff agent on Solari cloud browsers (see `architecture-direction.md`): always-on
watches and actions are a daily-use problem, the session replays make the demo self-evident,
and the launch post is a first-class release (`launch` sprint), not an afterthought.
